# Ядро ProxyYou

Использована версия Hiddify Core v4.1.0 и её закреплённые подмодули. Изменения мониторинга в `hiddify-sing-box/common/monitoring/outbound_monitoring.go`: по умолчанию 20 рабочих обработчиков, максимум 20; единственный URL — `https://www.youtube.com/generate_204`; дополнительные запросы определения IP после успешного URL-теста убраны. Они ранее выполнялись внутри проверки задержки и могли менять измеренную задержку по ответу другого сайта.

Патч: `youtube-monitoring.patch`. Применять из корня Hiddify Core командой `git apply /путь/к/youtube-monitoring.patch`. Подмодуль hiddify-sing-box: `0a02b7729f6a211436bb8bdcd8696c283eb27767`; ray2sing: `f58be84e30d946915a1de437fbcc3d3ffca18a23`. Остальные подмодули берутся по ссылкам этой версии.

Пересборка: Go 1.25.6. macOS arm64: `go build -trimpath -ldflags='-w -s -checklinkname=0 -buildid=' -tags=with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api,with_grpc,with_awg,tfogo_checklinkname0,with_naive_outbound,with_conntrack,with_dhcp -buildmode=c-shared -o hiddify-core.dylib ./platform/desktop`.

Android: gomobile/gobind v0.1.11, NDK 28.2.13676358, JDK 25. Команда из корня ядра: `CGO_LDFLAGS='-O2 -g -s -w -Wl,-z,max-page-size=16384' gomobile bind -androidapi=24 -javapkg=com.hiddify.core -libname=hiddify-core -tags=with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api,with_grpc,with_awg,tfogo_checklinkname0,with_naive_outbound,with_conntrack -trimpath -ldflags='-w -s -checklinkname=0 -buildid=' -target=android/arm,android/arm64,android/amd64 -o hiddify-core.aar github.com/sagernet/sing-box/experimental/libbox ./platform/mobile`. Опции `-gcflags 'all=-N -l'` из upstream Makefile намеренно не используются: они отключали оптимизацию и встраивание функций.

Поместить dylib в `hiddify-core/bin/hiddify-core.dylib`, AAR — в `android/app/libs/hiddify-core.aar`. Крупные бинарные зависимости исключены из архива исходников. Автоматическая загрузка исходного официального бинарника без патча вернёт прежний лимит.

Локальная проверка на macOS: из папки приложения `dart --packages=.dart_tool/package_config.json tools/test_core_workers.dart`. Стенд создаёт 60 SOCKS-конфигураций с локальным сервером, измеряет одновременные запросы до ответа сервера и проверяет адрес назначения. Все запросы отклоняются локально, реальные прокси не используются. Настройки системной сети не изменяются.

Лицензии upstream и ограничения на распространение сохраняются; это частная локальная сборка.

## Сохранение соединений

`connection-continuity.patch` выключает принудительный разрыв клиентских соединений в генерируемых группах `lowest`, `balance`, `select`. После выбора другого сервера новые соединения используют новый маршрут, открытые остаются на прежнем до завершения. При отказе прежнего транспорта сохранить его TCP-сессию невозможно. Пользовательские raw-конфиги не переписываются.

Применять патч из корня Hiddify Core ко всем целевым платформам, включая Android AAR. macOS/Windows-скрипты применяют его автоматически. Для Android сначала выполнить `patch -p1 < /путь/к/connection-continuity.patch`, затем `gomobile bind` по команде выше. Для проверки генератора: `go test ./v2/config -run TestProxyYou`. Для проверки переключения: `go test -v ./continuitycheck`. Стенд использует только локальные TCP/UDP и TLS, без изменения системных прокси. Дополнительные варианты hashing/sticky тестируются с явно заданными retry/TTL; основные Lowest/Round-robin — со штатными параметрами.

## Стабильность соединения 4.1.22

В `balance` группа сообщает последний сервер, через который успешно установлено
соединение, и уведомляет интерфейс о смене. До первого успешного соединения
сервер не выдумывается. Пинг относится к этому серверу; режим balance может
использовать разные серверы для разных одновременно открытых соединений.
Хранение выбора атомарное; тест `TestProxyYouBalanceReportsLastSuccessfulSelection`
проверяет чтение и обновление из нескольких потоков с `go test -race`.

После предыдущих патчей применяется `connection-stability.patch`: допуск только
проверенных серверов, ограниченные повторы установления через другие узлы,
перепроверка при смене сети, учёт IPv6 физического интерфейса, TTL DNS и безопасные
значения по умолчанию. Обработчики входящего TCP/UDP используют тот же путь
повторного установления, что и прямые вызовы ядра.

Применение: `bash scripts/apply-native-stability.sh /путь/к/core-source`.
Нативные сборки: `bash scripts/build-macos-core.sh /путь/к/core-source arm64`
(или `amd64`), `bash scripts/build-windows-core.sh /путь/к/core-source`,
`bash scripts/build-android-core.sh /путь/к/core-source` (Java 25).
Скрипты создают локальную запись SHA-256 ядра и патча; сборка приложения проверяет
её. Автоматическая подмена ядра официальной непатченной библиотекой отключена.

Проверки из корня ядра: `go test -race github.com/sagernet/sing-box/protocol/group/balancer
github.com/sagernet/sing-box/common/dialer github.com/sagernet/sing-box/common/monitoring -run TestProxyYou`,
`go test ./v2/config -run TestProxyYou`, `go test -race ./continuitycheck`.
Подробности: [VALIDATION-4.1.22.md](../docs/VALIDATION-4.1.22.md).

## Ошибки доступности важнее положительного пинга

`connection-stability.patch` также содержит сервис `proxyyou.Availability/Check`
(схема: `proxyyou_availability.proto`). Он принимает тег конкретного сервера и
выполняет GET к YouTube `generate_204` и к миниатюре тестового видео через один
и тот же outbound, без прямого обходного соединения. Групповые теги отклоняются.
Лимит 20 одновременно проверяемых серверов общий с обычными проверками пинга.

Ошибка HTTP, TLS, сети, тайм-аут или неверное содержимое помечают сервер
недоступным. Положительный пинг сохраняется внутри, но наружу возвращается
маркер недоступности; balance и lowest немедленно исключают сервер для новых
соединений. Уже открытые соединения принудительно не разрываются.
Снять отметку может только успешная проверка обоих адресов. Обычный пинг
недоступного сервера автоматически выполняет такую полную перепроверку.
Отметка сохраняется в кэше мониторинга при переподключении. Отмена, отключение,
смена сети и устаревший результат не меняют отметку.

Flutter использует отдельный канал управления для запроса; длительная проверка
не удерживает блокировку запуска/остановки ядра. Должны быть пересобраны все
нативные ядра: существующие бинарники с прежним отпечатком патча несовместимы
с этой функцией и не проходят проверку сборочных скриптов.

Дополнительные проверки: `go test -race ./v2/hcore
github.com/sagernet/sing-box/common/monitoring
github.com/sagernet/sing-box/protocol/group/balancer -run TestProxyYou`.

## Общая очередь пинга и большие подписки

Планировщик в `connection-stability.patch` больше не отбрасывает задания после
заполнения канала на 10 000 элементов. Очередь хранит не более одного ожидающего
задания на сервер, поддерживает ручной приоритет и обслуживается общим пулом
до 20 обработчиков. Флаг ожидания выставляется после успешного добавления.
Повторное ручное обращение поднимает существующее задание в приоритет, сохраняя
его канал результата, вместо запуска дубликата.

Сначала перепроверяются узлы с положительной предыдущей задержкой и без отметки
недоступности. Затем обработчики берут конфигурации поочерёдно из 20 равных
частей списка заданий в исходном порядке подписки. Обработчик не закреплён за
частью: медленный сервер не удерживает другие части. Порядок применяется как
к фоновому циклу, так и к ручной проверке подписки; вложенные группы обходятся
без повторных заданий. Результаты публикуются по мере завершения проверок.

Остановка отменяет ожидание, очищает очередь и таймеры повторов. Транспорт,
который ещё не готов, завершает задание текущего цикла ошибкой и получает одну
отложенную перепроверку; он не удерживает сборщик результатов бесконечно.

Проверки: `go test -race github.com/sagernet/sing-box/common/monitoring`.
Результаты и ограничения: [PING-QUEUE-VALIDATION.md](../docs/PING-QUEUE-VALIDATION.md).
Для распространения изменения требуется пересобрать нативные ядра и пакеты
всех платформ; отпечаток патча намеренно отличается от выпуска 4.1.25.
