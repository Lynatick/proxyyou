# Проверка общей очереди пинга

Локальное изменение от 25 октября 2026 года. Основа — ProxyYou 4.1.25,
коммит `cc45d4b3a80e719cb87bd023899cad75ed3f1a7e`.
Рабочая ветка: `codex/fair-ping-queue`.

## Изменение

- Общая очередь заменяет каналы фиксированного размера. Принятые задания
  не теряются после 10 000 конфигураций; отклонённое добавление не оставляет
  ложный флаг ожидания.
- Пул по-прежнему ограничен 20 проверками. Ранее отвечавшие серверы идут
  первыми, если они не помечены недоступными. Остальные задания чередуются
  между 20 равными частями списка. Свободный обработчик берёт следующую
  задачу из общей очереди, включая задачу из части с уже работающим медленным
  сервером. В каждой части сохраняется порядок выдачи заданий.
- Повторная ручная проверка поднимает ожидающую задачу в приоритет, сохраняя
  её результат для текущего фонового цикла. Активная проверка не дублируется.
- Ручная проверка работает до первого автоматического цикла. Вложенные группы
  не создают повторных заданий. Массовый запрос не пишет отдельный лог о
  постановке каждой конфигурации.
- Остановка очищает очередь; отмена между извлечением и запуском не оставляет
  флаги ожидания. Повтор готовности транспорта ограничен одним таймером на
  сервер и отменяется при остановке. Неготовый транспорт возвращает результат
  текущему циклу, поэтому сборщик не зависает.
- Правила недоступности, запрет возврата в balance/lowest по одному пингу,
  проверка сертификатов и сохранение открытых соединений не ослаблены.

## Что проверено

`go test -race` для `v2/hcore`, `v2/config`, `continuitycheck`, мониторинга и
балансировщика завершился успешно.

- Полный цикл на 33 726 и 65 734 контролируемых конфигурациях: получен результат
  каждой задачи, ровно одна попытка на сервер, максимум 20 одновременных
  попыток. Ошибочные серверы доступны для следующей перепроверки.
- Постановка ручной проверки всех 65 734 узлов без отсечения очереди.
- Сохранение всех узлов и приоритета при размерах 0, 1, 19, 20, 21, 43,
  33 726 и 65 734; равномерная первая волна из 20 частей.
- Ручное повышение приоритета, повторные запросы, завершение старой проверки
  при уже ожидающей новой, первый цикл с номером 0 и вложенные группы.
- Свободный обработчик продолжает другую задачу из части с медленным сервером.
- Остановка при 20 000 заданиях и отмена отложенного повтора; тестовый предел
  завершения остановки — две секунды.
- Отдельная проверка отложенного восстановления готовности транспорта.
- Прежние тесты доступности и её приоритета над пингом, смены сети, отмены
  и гонок результатов сохранились.
- TCP/UDP: переключения lowest, round-robin, hashing и sticky сохраняют уже
  открытые соединения; проверены повторы установления через другой сервер.

Это проверки планировщика на локальных управляемых отказах, не замер скорости
интернет-прокси. Время обработки десятков тысяч мгновенных отказов не является
обещанием времени проверки реальной подписки. Flutter-интерфейс не менялся.

## Воспроизводимость и распространение

Исходники изменений и тестов входят в `native-patches/connection-stability.patch`:
`common/monitoring/outbound_monitoring.go`, `test_task_queue.go`,
`test_task_queue_test.go` внутри подмодуля `hiddify-sing-box`.
Патч проверен на применение к исходной базе и повторное применение к уже
исправленным исходникам.

Код общий для macOS Silicon/Intel, Android и Windows. Пакеты и опубликованный
выпуск 4.1.25 не заменялись. Для установки исправления необходимо пересобрать
нативные ядра и пакеты; старые ядра не проходят проверку нового отпечатка патча.
