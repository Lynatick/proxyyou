# Приоритет ошибок доступности

Проверено локально 23 октября 2026 года. Изменения общие для macOS, Android и
Windows. Пакеты приложения и релиз GitHub в рамках этой проверки не выпускались.

## Поведение

- Обе сетевые проверки закреплены за одним конкретным сервером. Ошибка любого
  адреса, включая HTTP 404 миниатюры, делает конфигурацию недоступной независимо
  от положительного пинга или успешного ответа второго адреса.
- Balance и lowest сразу исключают такой сервер для новых соединений. Открытые
  соединения сохраняются. Отметка хранится в кэше мониторинга при переподключении.
- Для восстановления нужны успешные ответы обоих адресов. Повторный пинг
  недоступного сервера выполняет полную проверку. Отмена, смена сети, остановка
  ядра и устаревшие результаты не считаются отказом конфигурации.
- В списке и на главной отображается «Недоступна». Кнопка отключения остаётся
  доступной. Проверка доступности работает и при выключенном смешанном порте;
  воспроизведение по-прежнему использует смешанный порт и отсутствует в Windows.

## Результаты

- `flutter analyze --no-pub`: замечаний нет.
- Полный набор Flutter: 289 тестов прошли; после добавления двух тестов выбора
  маршрута дополнительно прошли 8 тестов маршрута, карточки и канала управления.
- `go test -race` для `v2/hcore`, `v2/config`, `continuitycheck`, мониторинга и
  балансировщика: успешно. Проверены приоритет ошибки над положительным пингом,
  восстановление, сохранение статуса, запоздалые ответы, отмена, смена сети,
  общий лимит 20 и немедленное исключение до отложенного уведомления группы.
- TCP/UDP: переключения сохраняют 100 обменов уже открытых соединений.
- Собрано тестовое ядро macOS arm64. `tools/test_core_workers.dart --availability`
  проверил настоящий запрос Flutter → gRPC → ядро, отказ группового тега,
  экспорт недоступности в список конфигураций и максимум 20 одновременных
  соединений. Все обращения выполнялись через локальный SOCKS-стенд;
  системные настройки прокси не менялись.
- Патч проверен на применение к исходной базе и повторное применение к уже
  исправленным исходникам. Для выпуска приложения требуется пересборка нативных
  ядер остальных платформ; старые ядра отвергаются по отпечатку патча.
