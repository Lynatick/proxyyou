# Конфигурации из SQLite

Подписки, параметры серверов, результаты проверок и выбор конфигурации работают
через таблицы. Ядро получает адрес каталога `proxyyou-db:…`, читает метаданные и
создаёт транспортный объект при первом использовании сервера. Сохранённого JSON
документа конфигурации между приложением и ядром больше нет.

## Обновление подписки

1. Ответ провайдера скачивается во временный файл `.download`. JSON, ссылки и
   другие поддерживаемые форматы существуют только на границе импорта.
2. Импортёр разбирает вход в типизированные параметры. Для получения метаданных
   он создаёт и закрывает один временный объект протокола за раз; одновременно
   создавать транспорты всей подписки не требуется.
3. Создаётся версия `staging`. Каждая конфигурация становится отдельной строкой
   `configuration_entries`; её параметры раскладываются в `configuration_fields`.
   Это типизированные значения, а не JSON в текстовой колонке. Сети и зависимости
   хранятся в собственных таблицах. Пакет записи — 128 конфигураций.
4. Завершённая версия становится `ready`; указатель `subscription_active`
   переключается одной транзакцией. Параллельное обновление проверяет, что
   предыдущая активная версия не изменилась. При ошибке остаётся прежняя версия.
5. После успешного импорта обновляются сведения о подписке в существующей БД
   приложения. Если добавление новой подписки в эту БД не удалось, при
   подтверждённом отсутствии записи профиля выполняется очистка её скрытого
   каталога. Эти две БД не объединены в одну общую транзакцию.
6. При работающем подключении ядро заменяет поставщиков параметров и состав
   групп в существующем экземпляре. Сокеты, входящие подключения, TUN и системные
   настройки прокси при чистом обновлении подписки не перезапускаются.

Статус прерванного процесса импорта учитывается через `configuration_imports`.
При следующем открытии БД незавершённые версии умершего процесса удаляются.
Действующий импорт не удаляется по таймеру или возрасту.

## Что хранится

Каталог находится в `data/configurations.db` рабочего каталога ядра. Используются
SQLite WAL, проверка внешних ключей, синхронизация FULL и ожидание занятой БД до
5 секунд. Для Unix применяется режим файла 0600; владелец учитывается через штатный
файловый менеджер ядра. В Windows действуют права каталога пользователя.

На Android служебные таблицы прежнего нативного хранилища (адрес настроек,
последний запрос запуска и ключи RPC) находятся во внутреннем `core-data`.
Эмулируемое внешнее хранилище может не поддерживать нужную им файловую
блокировку `flock`. Старые служебные таблицы копируются перед атомарной
публикацией нового каталога; оригиналы сохраняются. Этот перенос не меняет
пути подписок и каталога SQLite.

| Таблица | Данные |
|---|---|
| `subscription_revisions`, `subscription_active` | Версии подписки и активная версия |
| `configuration_entries` | Одна запись на конфигурацию: протокол, тег, порядок, отпечаток |
| `configuration_fields` | Отдельные типизированные поля параметров |
| `configuration_networks`, `configuration_dependencies` | Сети и зависимости |
| `configuration_status` | Задержка, недоступность, время, сеанс и поколение сети |
| `configuration_usage` | Счётчики трафика для сортировки |
| `configuration_selections` | Выбранный сервер или режим для подписки |
| `configuration_runtime` | Версия и сеанс, действительно используемые ядром |
| `configuration_revision_leases` | Версии, удерживаемые ядром и открытыми списками |
| `configuration_imports` | Владелец незавершённого импорта |
| `application_options`, `application_option_fields` | Версии настроек приложения в полях таблиц |

Каноническая схема — `native/database/schema.sql`, встроенная в Go. Приложение
читает её через отдельное соединение Drift в рабочем изоляте. Схемой каталога
владеет ядро; Drift не выполняет её миграции.

Существующая БД профилей приложения обновлена до версии 8: параметры пользователя
хранятся в колонках `profile_entries`, заголовки подписок — в `profile_headers`.
Старые JSON значения читаются только в миграции и затем очищаются. Прежние файлы
конфигураций сохраняются с суффиксом `.migrated`, но не используются при работе.
Повторный запуск прерванной миграции не заменяет более новую версию каталога.

Функции Dart с именами `toJson`/`fromJson` для моделей настроек могут по-прежнему
создавать обычные типизированные Map. Текстовый JSON из них для передачи ядру
не формируется: передаётся адрес версии `proxyyou-settings:…` в той же БД.

## Соединения и память

Метаданные всех серверов доступны для проверки и выбора, а параметры отдельного
протокола читаются по необходимости. Бездействующий кэш ограничен 128 объектами
исходящих соединений и 32 объектами конечных точек. Действующие соединения
удерживают свои поколения объектов сверх этого ограничения.

Изменённые параметры создают новое поколение для новых запросов. Предыдущее
поколение живёт до закрытия последнего TCP/UDP соединения. Изменение зависимости
также меняет отпечатки зависимых конфигураций. Удалённая конфигурация сразу
исчезает из выбора, сохраняя уже открытые соединения. Явное отключение закрывает
сокеты всех поколений, включая протоколы без собственного метода закрытия.
Ленивая обёртка сохраняет также поддержку прямой маршрутизации ICMP для
конечных точек WireGuard; такие маршруты удерживают своё поколение до закрытия.

Чистое обновление подписки не меняет экземпляр ядра. При ошибке завершающего
применения восстанавливается подготовленная типизированная копия прежней версии.
Изменение слушающих портов, DNS или маршрутизации сохраняет штатный путь полного
перезапуска; непрерывность при таких изменениях не обещается.

Работающую подписку нельзя удалить до подтверждённого отключения ядра.
Версии, удерживаемые ядром или списком, защищены от удаления. Кроме удерживаемых,
сохраняются две последние полные версии. Удаление подписки сначала помечает её
версии удалёнными; освобождение удержания завершает очистку. Удалённую версию
невозможно заново активировать или использовать для восстановления выбора.

## Проверки и интерфейс

Проверки остаются параллельными, до 20 одновременно. Результат относится к
версии каталога, сеансу ядра и поколению сети. Старые результаты не могут изменить
новую версию. Ошибка доступности имеет приоритет над положительным пингом и
исключает сервер из balance/lowest до успешной повторной проверки.

Список загружается SQL страницами по 100 записей. Порядок фиксируется для
открытого списка, чтобы проверки не перемещали элементы и фокус TV. Задержки
обновляются в уже загруженных строках. Главный экран получает только выбранную
цепочку, без копирования всей подписки после каждого пинга.

Логирование по умолчанию отключено одновременно в приложении и ядре. При этом
не создаются app.log/box.log, не заполняется история приложения и не открывается
поток журналов RPC. Пользователь может включить диагностику в настройках.
Явно сохранённый пользователем уровень журнала остаётся действующим.
Глобальный журнал нативного ядра также отключён до явного включения диагностики;
переключение его состояния безопасно при параллельной работе соединений.
Android не перенаправляет stderr в файлы без явного включения диагностики.

## Сборка и проверки

Новые нативные файлы находятся в `native/`; интеграция с закреплённым ядром —
`native-patches/database-source.patch`, поверх прежнего патча стабильности.
Все локальные помощники сборки ядра вызывают `scripts/apply-native-sources.sh`.
Проверка `native-core-stamp.py` включает хэш новых исходников и схемы, поэтому
прежнее ядро нельзя случайно упаковать с новым приложением.

Проверены миграции, совместимость настроек Dart/Go, страницы SQL, сохранение TCP
при обновлении, UDP поколения, закрытие сокетов, откат при намеренно вызванном
сбое активации и отсутствие гонок в выбранных пакетах ядра. Внешние прокси для
этих тестов не используются: тесты поднимают локальные серверы или используют
пары сокетов.

На сохранённых тестовых подписках импорт 33 728 записей занял около 5,2 секунды,
а 65 736 — около 11,8 секунды. Чтение типизированного источника заняло около
0,25 и 0,66 секунды соответственно на данном Mac. Это измерения импорта и
загрузки источника, а не времени проверки доступности или установления туннеля.

На 26 октября 2026 прошли 304 теста Flutter (два пропущены), анализ Dart без
замечаний и проверки выбранных нативных пакетов с детектором гонок. Полная
проверка преобразования параметров выполнена для всех 65 736 записей тестовой
подписки. Проверки каталога SQLite выполнены на macOS Silicon, Windows x64 и
Android TV, включая настройки, записанные Dart. В Windows проверено также
сохранение соединений при обновлении и откате ядра.

Проверочная компиляция для Mac Intel прошла. Запуск Intel-тестов на текущем Mac
недоступен: система возвращает `Bad CPU type in executable`. Это не проверка
готовых установочных пакетов: пакеты и нативные библиотеки для распространения
в рамках этой миграции ещё не пересобирались и не публиковались.
