# Оптимизация общего кода — ноябрь 2026

Изменения применимы к macOS Apple Silicon, Android/TV и Windows x64.

## Версии результатов в БД

Нативная схема конфигураций обновлена с версии 1 на 2. Миграция выполняется
в транзакции и сохраняет подписки, параметры и активные ревизии. Таблица
`configuration_change_versions` хранит отдельные версии статусов и трафика.
SQLite-триггеры меняют их при INSERT/UPDATE/DELETE в одной транзакции с данными;
откат записи откатывает и счётчик. Обновления без изменения отображаемых полей
не увеличивают версию. Сеанс и эпоха сети дополнительно входят в ключ статусов.

Flutter читает версии по первичным ключам вместо SUM по всем результатам.
Изменения незагруженных серверов тоже обнаруживаются. При неизменной версии
и том же окне страницы повторно не читаются, новое состояние не публикуется.

## Порядок и страницы

Во время поступления результатов автоматическое ранжирование объединяется:
не чаще одного раза за три секунды после предыдущего завершения, либо при
первом спокойном опросе. Проверки и накопление пинга при этом продолжаются.
Явный refreshStatus по умолчанию выполняет актуальное ранжирование сразу.

При первом открытии сохраняется прежний запрос с нумерацией; дополнительного
полного прохода нет. При первом повторном ранжировании уже вычисленные номера
копируются в TEMP-таблицу, затем используются повторно. Номер конфигурации
не меняется при сортировке по пингу/имени/трафику и при обратном порядке.
Ранжирование и чтение нужной страницы выполняются атомарно.

GridView имеет полную длину подписки, но читает только страницы вокруг viewport
с запасом по 100 строк. Например, переход к строке 3900 читает диапазон
3800–4099, а прежние объекты удаляются из окна. Возврат вверх повторно загружает
нужные страницы. Карта ключей тоже ограничена этим окном. Прокрутка, пришедшая
во время SQL-запроса, обрабатывается после его окончания.

## Осмотр файла

Скачивание по-прежнему завершается до обработки. Изолят читает файл чанками:
вычисляет SHA-256 исходных байтов, проверяет UTF-8, определяет формат и собирает
метаданные. На метаданные выделено не более 64 KiB и первых десяти строк.
Base64 обрабатывается потоково с проверкой всего содержимого; ошибочный хвост
не позволяет принять частично декодированные заголовки. Обычные JSON/URI/base64
подписки не сохраняются целиком ни в byte-массиве, ни в строке этого этапа.

Исключение — агрегатор с отдельными HTTP(S)-ссылками на подписки. Для него
требуется второй потоковый проход, чтобы вернуть строки раскрытия в исходном
порядке. Это позволяет не удерживать все строки обычного URI-файла на случай,
если ссылка встретится только в конце. Нативный импорт типизированных объектов
этими изменениями не переведён на потоковый парсер.
